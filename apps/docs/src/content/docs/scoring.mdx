`score` is the second stage and the guardrail's only model call. It hands the question and the surviving passages to a cheap model and gets back a number: how well those passages support an answer. It lives in `agent/pipeline.py` as `stage_score()`.

Similarity says *close*. Groundedness says *sufficient*. They fail differently, which is the whole reason this stage exists.

---

## The flow

```
stage_score()
  │
  ├─ passages                 surviving hits, numbered [1..k]
  │
  └─ _structured_call()       shared with the escalate stage
       ├─ system              prompts/<client_id>/score.md
       ├─ output_config       json_schema · never combined with citations
       └─ parse               → the four fields below
```

Two things come back: the parsed judgement, and the raw response — the latter only so token usage and cost land on the step.

| Field | What it is | Who reads it |
|---|---|---|
| `confidence` | `0.0`–`1.0`, how well the passages support an answer | The [guardrail](/configent/docs/escalation-guardrail) — **this is signal 2** |
| `supported` | The same judgement as a boolean | Nothing. Recorded only |
| `missing_info` | What the corpus lacked, in one phrase | A human reading the trail; the UI |
| `reasoning` | Why the model scored it that way | A human reading the trail; the UI |

---

## What the scorer is asked

The prompt is `prompts/<client_id>/score.md`, and its first instruction is that the scorer **judges the passages, it does not answer the question**. It is told what it is for: that low confidence stops the pipeline and files a ticket, and that the failure that matters is the opposite one — high confidence on passages that do not contain the answer, which produces a confident wrong answer to an infrastructure question.

It is given the question and the surviving passages, and calibrated against three bands:

| Band | Score | When |
|---|---|---|
| **High** | `0.8`–`1.0` | The passages state the answer directly — a default value, an error message and its documented cause, a named constraint, a described mechanism |
| **Middling** | `0.4`–`0.7` | On-topic and partly answering: the mechanism is described but the number asked for is absent, or one of two sub-questions is covered |
| **Low** | `0.0`–`0.3` | Topically adjacent without containing the answer; **or** the question depends on the user's own environment; **or** it is about a product outside this corpus |

Three details in that prompt do most of the work:

- **"Score this low however relevant the passages look."** Questions about a user's own project, quota, spend, org policy, cluster state or an open incident cannot be answered from public documentation, no matter how well retrieval matched. This is the rule that fires in the example below.
- **"Do not reward yourself for finding relevant-looking text."** The scorer is warned off the failure mode it is most prone to — mistaking topical proximity for an answer, which is exactly what similarity already measures.
- **`reasoning` is written for the end user.** The prompt says so, because that sentence renders in the step trail. It is a product string, not a debug log.

## A worked example

Both questions retrieve well. Only one of them can be answered.

**"What is the maximum request timeout on Cloud Run?"**

- Retrieval returned four passages, the best at `0.61`. The limit is stated verbatim in one of them.
- The scorer returns `confidence: 0.88`, `supported: true`.
- `0.88` clears `confidence_threshold: 0.6`, so the turn proceeds to [answering](/configent/docs/answering).

**"Can you raise my Cloud Run quota for europe-west1?"** — a real trace:

- Retrieval was *confident*: the corpus has a quotas-and-limits page, and it matched well.
- The environment rule fires. The question is about *this project's* quota in *this region*, which no public document can contain, so the scorer is instructed to score it low however good the match looked.
- The scorer returns `confidence: 0.05`, `supported: false`, `missing_info: "the user's own project quota"`, and the reasoning *"The passages describe quota limits generally, not this project's."*
- `0.05` is under the threshold, so the turn escalates. Cost of the judgement: `$0.000181`.

The second case is the one similarity alone cannot catch. The right document was retrieved; it just doesn't contain the answer.

## Design decisions

### The branch reads the number, not the boolean

The schema returns both. Only `confidence` is wired to anything, because a threshold outside the model is a threshold you can move, tune and defend.

| | **Threshold in Python, reading `confidence`** | Reading `supported` |
|---|---|---|
| **Where the bar lives** | One float in `config/*.yaml` | Inside the prompt and the weights |
| **Moving the bar** | Edit the number | Re-prompt, then re-evaluate |
| **Tuning it** | Sweep it offline over recorded scores | No dial to sweep |
| **What the trail shows** | `0.05 < 0.6` | `false` |
| **Who decides to escalate** | Python | The model |

Reading the boolean would put the escalation decision back inside the model, which is the thing this pipeline exists to avoid.

### The call itself

- **The threshold cuts the middling band in half.** `confidence_threshold: 0.6` sits inside the `0.4`–`0.7` range, so a partial answer scoring `0.65` is served and one scoring `0.55` escalates. That is intended — a partly-supported answer with citations is often useful — but it means the prompt's bands and the config's threshold have to be tuned together.
- **Its own prompt file.** `prompts/<client_id>/score.md`, separate from the answer prompt. A mega-prompt covering scoring and answering makes the guardrail unauditable.
- **The cheap model.** A judgement this narrow costs a fraction of the answering call — about `$0.0002` per step.
- **Structured output, never citations.** The Messages API returns 400 when `output_config.format` and citations are combined. `_structured_call()` is shared with the `escalate` stage, the other structured one.
- **`missing_info` is captured, not acted on.** It tells a human reading the trail *why* the corpus fell short. Nothing branches on it.
- **A malformed judgement escalates.** `score.get("confidence", 0.0)` — a missing key reads as zero, so the failure direction is a handoff to a human, never an answer.
- **Zero hits skip the stage entirely.** The scorer is never called with an empty passage list; `should_escalate()` receives `score=None` instead. A model asked to rate nothing still returns a number, and that number is fiction.

> **The honest limitation.** This is a model judging a model's inputs. It is cheap and narrow, which is why it works, but it is a second model call, not a proof. The deterministic signal from [retrieval](/configent/docs/retrieval) is what keeps the guardrail from resting on it alone.

## Configuration

| Key | Default | What it does |
|---|---|---|
| `agent.model` | — | The same model answers and scores. Cheap enough that a second call is not a design problem |
| `agent.confidence_threshold` | `0.6` | The bar this stage's `confidence` has to clear. Read by the branch, not here |

The threshold belongs to [The Guardrail](/configent/docs/escalation-guardrail); this stage only produces the number.
