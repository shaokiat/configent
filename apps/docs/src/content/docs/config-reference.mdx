<div class="lead">
  Every Configent client is defined by a single YAML file in <code>config/</code> at the
  repo root. This page documents every key, its type, default, and valid values.
  All keys are validated against a Pydantic schema at startup — invalid configs fail fast
  rather than at request time.
</div>

## Top-level keys

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `client_id` | `string` | ✓ | Unique identifier. Used as the pgvector namespace, URL slug, and log prefix. Must match `^[a-z0-9][a-z0-9-]*[a-z0-9]$`. |
| `name` | `string` | ✓ | Human-readable client name. Used in logs and the UI header. |

```yaml
client_id: acme-fab
name: "Acme Fab Equipment"
```

> This page uses **Acme Fab Equipment** as its running example: a documents-plus-one-tool client on
> the free-form [agent loop](/configent/docs/agent-loop), which exercises every key on this page.
> The demo deployment serves Cloud Platform Support alone, so Acme's config currently sits in
> `config/disabled/` — a directory the registry does not read. Write your own config to `config/`.

## `branding`

Controls UI presentation for this client.

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `branding.logo` | `string` | ✓ | Path to the client logo, relative to the repo root (e.g. `assets/acme-fab/logo.svg`). |
| `branding.primary_color` | `string` | ✓ | Hex colour used for the chat UI accent (e.g. `"#1B4F8A"`). |
| `branding.assistant_name` | `string` | ✓ | Name displayed in the chat header and used in the system prompt. |

```yaml
branding:
  logo: assets/acme-fab/logo.svg
  primary_color: "#1B4F8A"
  assistant_name: AcmeAssist
```

## `corpus`

Configures the document source and chunking settings.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `corpus.source` | `string` | — | Path to the document directory, relative to the repo root. All `.pdf`, `.md`, `.html`, and `.htm` files in the directory are ingested recursively. |
| `corpus.chunking.chunk_size` | `int` | `800` | Maximum tokens per chunk. Larger values preserve more context per retrieval hit. |
| `corpus.chunking.overlap` | `int` | `100` | Token overlap between adjacent chunks. Prevents mid-sentence splits from degrading retrieval quality. |

```yaml
corpus:
  source: corpora/acme-fab/
  chunking:
    chunk_size: 800   # the default — whole procedure steps survive intact
    overlap: 100
```

**Supported file types:** `.pdf`, `.md` / `.markdown`, `.html` / `.htm`.

**Embedding:** Configent embeds documents using **Voyage AI `voyage-3`** (1024-dimension vectors).
This requires a `VOYAGE_API_KEY` environment variable. The model is not configurable per client.

**Incremental ingestion:** The ingest step hashes each document's content. On re-run, it skips unchanged documents and re-chunks and re-embeds modified ones automatically.

## `agent`

Controls the engine, LLM, system prompt, and tool list for this client's agent.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `agent.mode` | `string` | `"loop"` | Which engine serves this client. `"loop"` is the free-form tool-use loop; `"graph"` is the three-tier support graph whose every route is a Python function. `"pipeline"`, the retired engine, is rejected at startup. See [The Support Graph](/configent/docs/support-graph). |
| `agent.model` | `string` | — | Claude model ID (e.g. `claude-haiku-4-5-20251001`, what all shipped clients use). |
| `agent.system_prompt_file` | `string` | — | Path to the system prompt file, relative to the repo root (e.g. `prompts/acme-fab.md`). Loaded at runtime, not inlined. |
| `agent.max_tokens` | `int` | `4096` | Maximum output tokens per API call. |
| `agent.effort` | `string` | `"medium"` | Claude extended-thinking effort level. One of `"low"`, `"medium"`, `"high"`, `"max"`. **Only applied on Sonnet 4+ and Opus 4+** — it is silently skipped for Haiku models (which all shipped clients use), so it is effectively inert today. See note below. |
| `agent.tools` | `list[string]` | `[]` | Ordered list of tool names to register for this client. Only tools listed here are available to the agent. Unknown names fail at startup. **Read by `loop.py` only.** Omit it in `graph` mode, where retrieval is a node and the ticket executor is invoked from Python. |
| `agent.retrieval_drop_floor` | `float` | `0.3` | Similarity below which a retrieved chunk is **discarded** before the model sees it. Applied by the graph's `retrieve` node and the dense half of Level 2; the loop's `search_docs` tool uses `search()`'s own `0.3` default instead. |
| `agent.escalate_below` | `float` | `0.45` | Similarity below which the best surviving chunk **fails Level 1**. Graph mode only; Level 2 has no cosine floor. |
| `agent.confidence_threshold` | `float` | `0.6` | Groundedness score below which a level **falls short**. Graph mode only; applies at both levels. |
| `agent.corrective.enabled` | `bool` | `true` | Whether a turn that fails Level 1 gets [corrective retrieval](/configent/docs/corrective-retrieval) or goes straight to a ticket offer. Graph mode only. |
| `agent.corrective.query_rewrites` | `int` | `3` | Query variants the Level 2 rewrite returns, each embedded and searched. Between 1 and 5. Graph mode only. |

```yaml
agent:
  mode: graph
  model: claude-haiku-4-5-20251001
  system_prompt_file: prompts/gcp-platform-support/answer.md
  max_tokens: 2048
  effort: low
  retrieval_drop_floor: 0.3
  escalate_below: 0.45
  confidence_threshold: 0.6
  corrective:
    enabled: true
    query_rewrites: 3
  # No `tools:` key: graph mode never sends tool definitions.
```

> **Falling short of a threshold does not file a ticket.** At Level 1 it sends the turn to
> Level 2, or to a conversational reply if the grader called it a greeting. At Level 2 it
> produces a drafted ticket the user is asked to confirm. See
> [The Guardrail](/configent/docs/escalation-guardrail).

> **`escalate_below` must exceed `retrieval_drop_floor`.** They act on the same number at
> different points: the drop floor discards, the escalate floor routes. If the escalate
> floor were the lower of the two, it could never fire — every surviving hit is at or above
> the drop floor by construction. The config validator rejects that relationship at
> startup. See [The Guardrail](/configent/docs/escalation-guardrail).

> **Graph mode expects four prompt files.** `agent.system_prompt_file` points at
> `answer.md`; `grade.md`, `rewrite.md` and `ticket_draft.md` must sit beside it in the same
> directory.

> **`effort` and Haiku:** extended thinking is only supported on Sonnet 4+ and Opus 4+. The loop
> (`loop.py`) checks the model name and only sends `effort`/`thinking` when the model is *not* Haiku.
> Every shipped client runs Haiku, so the loop accepts and validates the `effort` key but never sends it to the API. Switch a client to a Sonnet or Opus model and `effort` takes effect.

> **Prompt caching:** The system prompt is always cached at the turn breakpoint using
> Anthropic's ephemeral cache. This is unconditional — no config needed. The loop sorts tool definitions alphabetically before each request to ensure a stable cache prefix.

> **Max iterations:** The agent loop runs for a maximum of **8 iterations** regardless of config.
> If the loop hasn't completed in 8 tool-call cycles it raises an error. Graph mode has no
> iteration cap: it runs one pass, at most seven nodes per turn.

### Available tools

| Tool name | Scope | Description |
|-----------|-------|-------------|
| `search_docs` | Shared | Semantic search over the client's pgvector namespace. Returns `search_result` blocks with citations enabled. Accepts `query` (required) and `k` (default 5, max 8). |
| `get_document` | Shared | Retrieves full document text by `document_id` (as returned by `search_docs`). Use when a chunk doesn't contain enough context. |
| `create_escalation_ticket` | `gcp-platform-support` | POSTs a ticket to the [mock ticket service](/configent/docs/mock-ticket-service) over HTTP with an idempotency key; the service assigns the id. In graph mode its definition is never sent to a model: Python calls the executor directly. |
| `pricing_lookup` | `acme-fab` | Returns unit price, volume discount, and lead time for an Acme part number and quantity. |
| `coverage_check` | `meridian-insurance` | Returns a structured coverage verdict for a named claim scenario against the HomeShield Plus policy. |

`search_docs` and `get_document` are shared and can be added to any client. `create_escalation_ticket`,
`pricing_lookup`, and `coverage_check` are client-specific — they contain hardcoded ticketing,
catalog, or policy data specific to those clients. Adding a new client-specific tool requires adding
a file under `apps/api/app/tools/<client_id>/` and registering it in `apps/api/app/tools/registry.py`.

## `limits`

Controls per-client rate limiting and cost guardrails.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `limits.rate_limit_per_minute` | `int` | `20` | Maximum requests per minute for this client. |
| `limits.daily_budget_usd` | `float` | `2.00` | Maximum spend in USD per day. Requests are rejected once the budget is exhausted. |

```yaml
limits:
  rate_limit_per_minute: 20
  daily_budget_usd: 2.00
```

---

## `evals` (optional)

Configures automated evaluation against a golden Q&A set. Omit if not using evals.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `evals.golden_set` | `string` | — | Path to a `.jsonl` file of `{question, expected_answer}` pairs, relative to the repo root. |
| `evals.judge_model` | `string` | `claude-sonnet-4-6` | Claude model used as the LLM judge for eval scoring. |

```yaml
evals:
  golden_set: evals/acme-fab/golden.jsonl
  judge_model: claude-sonnet-4-6
```

## Complete example

This is the actual `acme-fab` client config from the repo (`config/disabled/acme-fab.yaml`):

```yaml
client_id: acme-fab
name: "Acme Fab Equipment"

branding:
  logo: assets/acme-fab/logo.svg
  primary_color: "#1B4F8A"
  assistant_name: "AcmeAssist"
  suggested_questions:
    - "What's the preventive maintenance schedule for the PX-900?"
    - "How much does the chamber seal kit cost and when does it need replacing?"
    - "What safety precautions apply when venting the PX-900 chamber?"

corpus:
  source: corpora/acme-fab/
  chunking:
    chunk_size: 800
    overlap: 100

agent:
  model: claude-haiku-4-5-20251001
  system_prompt_file: prompts/acme-fab.md
  max_tokens: 4096
  effort: medium
  tools:
    - search_docs
    - get_document
    - pricing_lookup

evals:
  golden_set: evals/acme-fab/golden.jsonl
  judge_model: claude-sonnet-4-6

limits:
  rate_limit_per_minute: 20
  daily_budget_usd: 2.00
```
