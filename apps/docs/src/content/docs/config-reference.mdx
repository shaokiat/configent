<div class="lead">
  Every Configent client is defined by a single YAML file in <code>config/</code> at the
  repo root. This page documents every key, its type, default, and valid values.
  All keys are validated against a Pydantic schema at startup — invalid configs fail fast
  rather than at request time.
</div>

## Top-level keys

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `client_id` | `string` | ✓ | Unique identifier. Used as the pgvector namespace, URL slug, and log prefix. Must match `^[a-z0-9][a-z0-9-]*[a-z0-9]$`. |
| `name` | `string` | ✓ | Human-readable client name. Used in logs and the UI header. |

```yaml
client_id: gcp-platform-support
name: "Cloud Platform Support"
```

> This page uses **Cloud Platform Support**, the client the repo ships, as its running example.
> Its file is `config/gcp-platform-support.yaml`.

## `branding`

Controls UI presentation for this client.

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `branding.logo` | `string` | ✓ | Path to the client logo, relative to the repo root. |
| `branding.primary_color` | `string` | ✓ | Hex colour used for the chat UI accent. |
| `branding.assistant_name` | `string` | ✓ | Name displayed in the chat header. |
| `branding.tagline` | `string` | | Empty-state copy. Unset, the UI falls back to a generic line. |
| `branding.suggested_questions` | `list[string]` | | Up to 5 starter questions shown on an empty chat. |

```yaml
branding:
  logo: assets/gcp-platform-support/logo.svg
  primary_color: "#1a73e8"
  assistant_name: "DeployBot"
  suggested_questions:
    - "My Cloud Run container fails to start — what does the PORT error mean?"
    - "Can you raise my Cloud Run instance quota for europe-west1?"
```

## `corpus`

Configures the document source and chunking settings.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `corpus.source` | `string` | — | Path to the document directory, relative to the repo root. All `.pdf`, `.md`, `.html`, and `.htm` files in the directory are ingested recursively. |
| `corpus.chunking.chunk_size` | `int` | `800` | Maximum tokens per chunk. Larger values preserve more context per retrieval hit. |
| `corpus.chunking.overlap` | `int` | `100` | Token overlap between adjacent chunks. Prevents mid-sentence splits from degrading retrieval quality. |

```yaml
corpus:
  source: corpora/gcp-platform-support/
  chunking:
    chunk_size: 512
    overlap: 64
```

**Supported file types:** `.pdf`, `.md` / `.markdown`, `.html` / `.htm`.

**Embedding:** Configent embeds documents using **Voyage AI `voyage-3`** (1024-dimension vectors).
This requires a `VOYAGE_API_KEY` environment variable. The model is not configurable per client.

**Incremental ingestion:** The ingest step hashes each document's content. On re-run, it skips unchanged documents and re-chunks and re-embeds modified ones automatically.

## `agent`

Controls the model, prompts and guardrail thresholds of this client's [support graph](/configent/docs/support-graph).

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `agent.model` | `string` | — | Claude model ID. Every model call in the graph uses it. It must have a row in [`config/pricing/claude.yaml`](#model-pricing), or startup fails. The shipped client runs `claude-haiku-4-5-20251001`. |
| `agent.system_prompt_file` | `string` | — | Path to the answering prompt, relative to the repo root. `grade.md`, `rewrite.md` and `ticket_draft.md` must sit beside it. |
| `agent.max_tokens` | `int` | `4096` | Maximum output tokens for the answering call. The grade, rewrite and draft calls have fixed limits. |
| `agent.retrieval_drop_floor` | `float` | `0.3` | Similarity below which a retrieved chunk is **discarded** before the model sees it. Applied by `retrieve` and the dense half of Level 2. |
| `agent.escalate_below` | `float` | `0.45` | Similarity below which the best surviving chunk **fails Level 1**. Level 2 has no cosine floor. |
| `agent.confidence_threshold` | `float` | `0.6` | Groundedness score below which a level **falls short**. Applies at both levels. |
| `agent.corrective.enabled` | `bool` | `true` | Whether a turn that fails Level 1 gets [corrective retrieval](/configent/docs/corrective-retrieval) or goes straight to a ticket offer. |
| `agent.corrective.query_rewrites` | `int` | `3` | Query variants the Level 2 rewrite returns, each embedded and searched. Between 1 and 5. |

```yaml
agent:
  model: claude-haiku-4-5-20251001
  system_prompt_file: prompts/gcp-platform-support/answer.md
  max_tokens: 2048
  retrieval_drop_floor: 0.3
  escalate_below: 0.45
  confidence_threshold: 0.6
  corrective:
    enabled: true
    query_rewrites: 3
```

> **Unknown keys fail at load.** `AgentConfig` forbids extra keys. `mode`, `tools` and `effort`
> belonged to the [retired loop engine](/configent/docs/retiring-the-loop), and a config that
> still sets one is rejected rather than silently ignored.

> **Falling short of a threshold does not file a ticket.** At Level 1 it sends the turn to
> Level 2, or to a conversational reply if the grader called it a greeting. At Level 2 it
> produces a drafted ticket the user is asked to confirm. See
> [The Guardrail](/configent/docs/escalation-guardrail).

> **`escalate_below` must exceed `retrieval_drop_floor`.** They act on the same number at
> different points: the drop floor discards, the escalate floor routes. If the escalate
> floor were the lower of the two, it could never fire, because every surviving hit is at or
> above the drop floor by construction. The config validator rejects that relationship at
> startup. See [The Guardrail](/configent/docs/escalation-guardrail).

> **One pass, no iteration cap.** A turn runs at most seven nodes: Level 1, Level 2, the
> ticket offer and the ticket itself.

## Model pricing

```yaml
# config/pricing/claude.yaml — USD per million tokens
claude-haiku-4-5-20251001:
  input: 1.00
  output: 5.00
  cache_write: 1.25   # the 5-minute TTL
  cache_read: 0.10
```

Every `cost_usd` in the system comes from this table: the step trail, the `done` event, the conversation total and the daily budget check. It is one file for the deployment, keyed by the exact model id a client config uses.

- **Checked in and dated.** Anthropic publishes prices on its [pricing page](https://platform.claude.com/docs/en/about-claude/pricing); no API returns them.
- **Copy every column.** Cache rates are listed per model; don't derive them from a multiplier.
- **An unpriced model fails startup.** The registry calls `price_for(agent.model)` for every client at load.
- **An estimate, not the bill.** Billed cost comes from the Admin API cost report. See [Decisions → Known gaps](https://github.com/shaokiat/configent/blob/main/docs/decisions.md#part-3--known-gaps).

## `limits`

Controls per-client rate limiting and cost guardrails.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `limits.rate_limit_per_minute` | `int` | `20` | Maximum requests per minute for this client. |
| `limits.daily_budget_usd` | `float` | `2.00` | Maximum spend in USD per day, at the rates in `config/pricing/claude.yaml`. Requests are rejected once the budget is exhausted. |

```yaml
limits:
  rate_limit_per_minute: 60
  daily_budget_usd: 2.00
```

## `evals` (optional)

Configures automated evaluation against a golden set. Omit if not using evals.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `evals.golden_set` | `string` | — | Path to a `.jsonl` golden set, relative to the repo root. |
| `evals.judge_model` | `string` | `claude-sonnet-4-6` | Claude model used as the LLM judge for eval scoring. |

```yaml
evals:
  golden_set: evals/gcp-platform-support/golden.jsonl
  judge_model: claude-sonnet-4-6
```

## Complete example

The shipped `config/gcp-platform-support.yaml`, with comments and the tagline trimmed:

```yaml
client_id: gcp-platform-support
name: "Cloud Platform Support"

branding:
  logo: assets/gcp-platform-support/logo.svg
  primary_color: "#1a73e8"
  assistant_name: "DeployBot"
  suggested_questions:
    - "My Cloud Run container fails to start — what does the PORT error mean?"
    - "Why won't my GKE node pool scale down after I deleted the workload?"
    - "Can you raise my Cloud Run instance quota for europe-west1?"

corpus:
  source: corpora/gcp-platform-support/
  chunking:
    chunk_size: 512
    overlap: 64

agent:
  model: claude-haiku-4-5-20251001
  system_prompt_file: prompts/gcp-platform-support/answer.md
  max_tokens: 2048
  retrieval_drop_floor: 0.3
  escalate_below: 0.45
  confidence_threshold: 0.6
  corrective:
    enabled: true
    query_rewrites: 3

evals:
  golden_set: evals/gcp-platform-support/golden.jsonl
  judge_model: claude-sonnet-4-6

limits:
  rate_limit_per_minute: 60
  daily_budget_usd: 2.00
```
