`answer` runs when either level's route says the evidence holds. It sends that level's passages, numbered, and the question to the model, and streams the reply, turning each `[n]` the model writes into a citation (D15). `answer_request_kwargs()` in `agent/templates/documents.py` assembles the request.

The interesting part of that request is what is missing from it.

---

## The flow

```
answer(state)
  │
  ├─ answer_request_kwargs()  → (request, passages)
  │     "[1] title (source)\n text …" (passages first) + the question (last)
  │     system prompt (cache breakpoint) · history · no `tools` key
  ▼
chat completions (streaming), any OpenRouter model
  │  text ──▶ Markers ──┬─ text   ──▶ stream writer ──▶ SSE `text`
  │                     └─ [n]    ──▶ stream writer ──▶ SSE `citation`, as it completes
  ▼
segments_from(pieces, passages)         agent/common.py
  └─▶ state: answer · citations · segments · outcome="answer"
```

There is no `tools` key in the request. Not an empty list: the key never appears, and neither does the ticket tool's name. A test asserts both on the real request.

`Markers` and `segments_from()` live in `agent/common.py`, beside the conversation and cost helpers, so the stored `segments` format has one owner.

---

## A worked example

**"My Cloud Run container fails to start — what does the PORT error mean?"** A real run.

- Level 1 passed it on similarity `0.62` and groundedness `0.95`, with five passages.
- The request goes out as five numbered passages followed by the question, plus the system prompt. No tools.
- The reply streams as `text` events, and a `citation` event each time the model writes a valid `[n]`. Four arrived.
- The step records `level: 1`, `n_citations: 2`, and the guardrail's sentence as its reasoning. The node took 2.5 s; the whole turn cost $0.026.

The follow-up in the same conversation reached this node from Level 2. Same request shape, built from the Level 2 passages instead, and a step with `level: 2` and three citations.

## Design decisions

### The model has nothing to escalate with

Escalation is not this node's decision, and the enforcement is structural rather than written down.

| | **No `tools` key (built)** | Tools present, prompt says "don't escalate" |
|---|---|---|
| **Can it file a ticket?** | No, the capability is absent | Yes, if it decides to |
| **Can it decline by escalating?** | No | Yes, the easy out on any hard question |
| **What enforces it** | The API request | A sentence the model weighs against others |
| **How you verify it** | Assert on the request in a test | Re-run the evals and hope |

Prompting a model not to do something it can do is a request. Removing the capability is a guarantee.

### The request itself

- **Passages first, question last.** The evidence is context; the question is the instruction.
- **Every passage is numbered, and only those numbers cite.** A marker naming no passage stays in the text and counts in `bad_citations` on the step.
- **The system prompt carries a cache breakpoint.** It is inert on Haiku 4.5, whose minimum cacheable prefix is longer than `answer.md`. See [Prompt Caching](/configent/docs/prompt-caching).
- **Deltas go through LangGraph's stream writer.** The node writes `("text", …)` and `("citation", …)` tuples, and `stream_turn()` forwards them unchanged. See [SSE Streaming](/configent/docs/sse-streaming#how-graph-nodes-stream).
- **Citations are parsed, not generated by the API.** The marker is the model's claim; Python checks only that it names a passage (D15).
- **This node never sees empty retrieval.** Both decide functions require at least one passage before they route here.
- **An answer that cites nothing is visible, not blocked.** `n_citations: 0` on the step reads as a corpus problem rather than a wiring one.

## Configuration

| Key | Default | What it does |
|---|---|---|
| `agent.model` | none | The model that answers. The same one grades |
| `agent.max_tokens` | `4096` | Cap on the streamed reply |
| `agent.system_prompt_file` | none | The answer prompt. `grade.md`, `rewrite.md` and `ticket_draft.md` are resolved beside it |
