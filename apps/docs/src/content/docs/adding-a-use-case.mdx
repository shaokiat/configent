  deciding what the corpus can answer and writing prompts that hold that line.

## The anatomy of a client

| Artifact | Path | Controls |
|----------|------|----------|
| **Config** | `config/<id>.yaml` | Identity, branding, model, thresholds, limits |
| **Corpus** | `corpora/<id>/` | The documents the assistant answers from (`.md`, `.pdf`, `.html`) |
| **Prompts** | `prompts/<id>/` | `answer.md`, `grade.md`, `rewrite.md`, `ticket_draft.md` |
| **Branding asset** | `assets/<id>/logo.svg` | The logo shown in the chat UI |
| **Sentinels** *(recommended)* | `evals/sentinels.yaml` | Facts planted verbatim, so retrieval tests have ground truth |
| **Golden set** *(optional)* | `evals/<id>/golden.jsonl` | The expected outcome for each test question |

A model not yet in `config/pricing/claude.yaml` also needs a price row there.

---

## The one decision: what can the corpus never know?

The graph answers what the corpus supports and offers a ticket for the rest. Write that
boundary down before writing a prompt.

| Answerable from documentation | Needs a human |
|---|---|
| What a default, limit or error message means | Anything about the user's own account or project |
| How a documented mechanism behaves | A change: quota, access, billing |
| Which documented cause fits a symptom | Whether an incident is happening right now |

Cloud Platform Support's corpus is public Google Cloud documentation. "What does the PORT error
mean?" is answerable. "Raise my quota" structurally is not, however relevant the retrieved
passages look. `grade.md` names that second column explicitly, which is what lets the grader
score it low.

## Walkthrough: Cloud Platform Support

### 1. Plant the corpus

`corpora/gcp-platform-support/` holds 10 pages of public Google Cloud documentation (CC BY 4.0,
attributed per file) across Cloud Run, GKE and IAM.

> **Getting source documents into a corpus.** Strip frontmatter and components so chunks
> contain prose, not markup. Keep each key fact on a single line so it survives chunking and can
> be cited verbatim. The corpus is a *snapshot*: re-run ingestion to refresh it.

Add a few sentinel facts to `evals/sentinels.yaml`, each a sentence copied verbatim from one
document. `test_sentinels.py` checks that every sentinel appears in its document and in no other
client's corpus.

### 2. Write the four prompts

`agent.system_prompt_file` points at `answer.md`; the other three must sit beside it.

| File | Call | What it has to say |
|---|---|---|
| `answer.md` | Streaming, with citations | The persona; answer only from the passages; cite |
| `grade.md` | Structured output | What the corpus can never know; the confidence bands; what counts as `conversation` or `handoff` |
| `rewrite.md` | Structured output | How to turn a follow-up into standalone queries and exact keywords |
| `ticket_draft.md` | Structured output | How to write a subject and body the support team can act on |

Start from `prompts/gcp-platform-support/` and rewrite the domain parts. Each prompt's structure,
and the fields it asks the model to return, stay the same.

> **Some of the ticket path is still written for one queue.** The draft schema's `category` and
> `product_area` values (`cloud_run`, `gke`, `iam`), the wording of the ticket offer, and the
> greeting fallback live in `agent/graph.py`. A client with a different support queue needs those
> moved to config first.

### 3. Write the config

`config/gcp-platform-support.yaml`, with comments trimmed:

```yaml
client_id: gcp-platform-support
name: "Cloud Platform Support"

branding:
  logo: assets/gcp-platform-support/logo.svg
  primary_color: "#1a73e8"
  assistant_name: "DeployBot"
  suggested_questions:
    - "My Cloud Run container fails to start — what does the PORT error mean?"
    - "Why won't my GKE node pool scale down after I deleted the workload?"
    - "Can you raise my Cloud Run instance quota for europe-west1?"

corpus:
  source: corpora/gcp-platform-support/
  chunking:
    chunk_size: 512
    overlap: 64

agent:
  model: claude-haiku-4-5-20251001
  system_prompt_file: prompts/gcp-platform-support/answer.md
  max_tokens: 2048
  retrieval_drop_floor: 0.3
  escalate_below: 0.45
  confidence_threshold: 0.6
  corrective:
    enabled: true
    query_rewrites: 3

limits:
  rate_limit_per_minute: 60
  daily_budget_usd: 2.00
```

- **Start with the default thresholds.** Tune them against a golden set, not against one answer that looked wrong.
- **One suggested question per branch.** An answer from one document, a synthesis, and a question only a human can act on.

### 4. Add a branding asset

Drop a `logo.svg` into `assets/gcp-platform-support/`. The UI reads `branding` to render a chat
that looks like the client's own product.

### 5. Ingest and try it

```bash
cd apps/api
uv run python -m app.cli --client gcp-platform-support
```

Open `/c/gcp-platform-support` and ask the suggested questions. Re-running ingest is safe:
unchanged documents are skipped, changed ones are re-embedded.

## What the platform validates for you

The registry checks every config when it first loads:

- **Config schema:** a malformed config fails with an error naming the field and the file.
- **Unknown keys fail.** A typo in an `agent` key, or a leftover `tools` from the retired loop engine, is rejected rather than ignored.
- **An unpriced model fails.** `agent.model` must have a row in `config/pricing/claude.yaml`.
- **An unreachable guardrail fails.** An `escalate_below` at or under `retrieval_drop_floor` could never fire, so it is refused.
- **Tenant isolation** is enforced at the query level, filtering retrieval by `client_id`. See [Multi-Tenancy](/configent/docs/multi-tenancy).

## New use case in five steps

```text
corpora/<id>/            1. Drop in documents, plant a few sentinels
prompts/<id>/            2. Write answer.md, grade.md, rewrite.md, ticket_draft.md
config/<id>.yaml         3. Write the config (and a price row for a new model)
assets/<id>/logo.svg     4. Add branding
python -m app.cli        5. --client <id>, then open /c/<id>
```

No Python for a client whose tickets go to the same kind of queue. If something doesn't
validate, the error names the field and the file.
