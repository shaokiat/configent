## Cloud Platform Support

**Use case:** A deployment and infrastructure support agent. **DeployBot** answers Cloud Run, GKE
and IAM questions from public Google Cloud documentation with citations, and offers a drafted
ticket when a question depends on the user's own project — quota, billing, IAM policy, cluster
state. Nothing is filed until the user confirms, and a turn that is not a support request at
all, such as a greeting or a thank-you, is answered conversationally and files nothing. This is
the assistant powering the [demo](/configent/demo).

**Corpus:** A curated snapshot of public Google Cloud documentation (CC BY 4.0, attributed per
file) in `corpora/gcp-platform-support/`: 10 files across Cloud Run, GKE, and IAM.

**What's notable:**
- Every route, from answer to a second search to a human, is a Python function, not a tool the
  model may call. See [The Support Graph](/configent/docs/support-graph).
- Three thresholds instead of one: `retrieval_drop_floor` discards weak chunks, and
  `escalate_below` and `confidence_threshold` decide when a tier falls short. See
  [The Guardrail](/configent/docs/escalation-guardrail).
- A `corrective` block turns on Level 2: a query rewrite and hybrid search before any ticket
  is offered. See [Corrective Retrieval](/configent/docs/corrective-retrieval).
- The corpus contains nothing about any user's own project, which is what makes the escalation
  branch load-bearing rather than decorative. "What does the platform do?" is answerable;
  "what is *my* project doing?" structurally is not.
- The ticket client, `app/tickets.py`, makes a real HTTP POST to a
  [separate service](/configent/docs/mock-ticket-service), which assigns the ticket id.

```yaml
client_id: gcp-platform-support
name: "Cloud Platform Support"

branding:
  logo: assets/gcp-platform-support/logo.svg
  primary_color: "#1a73e8"
  assistant_name: "DeployBot"

corpus:
  source: corpora/gcp-platform-support/
  chunking:
    chunk_size: 512
    overlap: 64

agent:
  model: claude-haiku-4-5-20251001
  system_prompt_file: prompts/gcp-platform-support/answer.md
  max_tokens: 2048
  retrieval_drop_floor: 0.3
  escalate_below: 0.45
  confidence_threshold: 0.6
  corrective:
    enabled: true
    query_rewrites: 3

evals:
  golden_set: evals/gcp-platform-support/golden.jsonl
  judge_model: claude-sonnet-4-6

limits:
  rate_limit_per_minute: 60
  daily_budget_usd: 2.00
```

> **No `tools`, `mode` or `effort` keys.** Retrieval is a node and the ticket client is called
> from Python, so no tool definition is ever sent to a model for this client. The schema
> rejects all three keys: they belonged to the retired loop engine. See
> [Retrieval → Retrieval is a node, not a tool](/configent/docs/retrieval#retrieval-is-a-node-not-a-tool).

## Earlier clients

**Acme Fab Equipment** and **Meridian Insurance** ran on the free-form loop engine, each with its
own tool (`pricing_lookup`, `coverage_check`). Neither was loaded by the demo, and both were
removed with the loop in D11. Their configs, corpora and prompts are recoverable from git:
see [Retiring the Loop](/configent/docs/retiring-the-loop#recovering-the-retired-design).
