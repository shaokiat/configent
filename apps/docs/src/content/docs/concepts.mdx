## What it has to do

Four requirements, and every design decision below traces back to one of them.

1. **Answer only from the evidence, with citations.** An uncited claim is a failure, not a style choice.
2. **Know when it cannot answer.** The interesting half of an assistant is the refusal, and that decision has to be explainable after the fact.
3. **Serve many clients from one deployment.** Adding a tenant of an existing template is a config file, sources and prompts, with no Python.
4. **Leave a record.** Every turn has to be auditable, and the record has to survive the process dying mid-turn.

## One platform, two templates

```
                        config/<client>.yaml
                                │  agent.template
                ┌───────────────┴────────────────┐
                ▼                                ▼
   documents  (DeployBot)              database  (PitWall)
   retrieve → grade                    generate → guard → execute
     └─ rewrite → hybrid_retrieve        └─ repair → guard → execute
          → regrade                                │
                │                                  │
                └──────────────┬───────────────────┘
                               ▼
          the platform: answer with [n] citations · converse
                        · decline or escalate → ticket (on confirm)
          + limits · run trail · checkpoints · SSE · cost
```

**Templates find evidence; the platform decides what to do with it.** Every arrow is chosen by a plain Python function. No model is ever sent a tool, so no model can choose to escalate.

| | [DeployBot](/configent/docs/deploybot) | [PitWall](/configent/docs/pitwall) |
|---|---|---|
| **Template** | `documents` | `database` |
| **Evidence** | Public Cloud Run, GKE and IAM docs | A Formula 1 results database, 1950 to 2017 |
| **Finds it by** | Dense search, then rewrite and hybrid search | One model-written SELECT, guarded, repaired once |
| **Can't answer means** | The question depends on the user's own project | Newer data, or a change to the data |
| **Hands off to** | The platform team, as a ticket | The data team, as a ticket |

Start with the use-case pages for what each client does, then [One Turn, End to End](/configent/docs/one-turn) for what the platform does for both.

## The shape

```
Next.js (chat UI)            apps/web
      │  SSE
FastAPI                      apps/api
      ├─ config registry      one YAML per client, validated at startup
      ├─ templates            documents · database, each a LangGraph graph
      ├─ platform             limits · run trail · checkpoints · handoff nodes · cost
      ├─ OpenRouter           every model call, OpenAI SDK, DeepSeek V4.1 Flash by default
      ├─ Voyage               embeddings, documents template only
      ├─ SQLite (read-only)   the database template's evidence
      └─ Postgres             conversations · messages · chunks · runs · checkpoints · traces
                                    │  HTTP
                              mock ticket service   apps/mockticket
```

## The stack, and why

| Layer | Choice | Why this one |
|---|---|---|
| LLM | Any model on OpenRouter, through the OpenAI SDK. DeepSeek V4.1 Flash for every call | One SDK and one bill for any model. 24× cheaper per turn than all-Haiku on the demo questions, with the same routes and facts. [Model Calls](/configent/docs/model-calls) |
| Embeddings | Voyage `voyage-3` | Exposes `input_type` query/document, a [free recall win](/configent/docs/ingestion-pipeline#why-voyage-ai) |
| Vector and keyword search | pgvector + Postgres full-text | Already inside the Postgres we need. A dedicated search service would be a [second system for no gain at this scale](/configent/docs/ingestion-pipeline#voyage-ai-vs-pgvector) |
| Agent runtime | LangGraph, for checkpoints and the ticket pause | Model calls, routing and citations stay plain code. [How the Graphs Are Built](/configent/docs/langgraph) |
| Backend | FastAPI + async SQLAlchemy | Native `async` all the way down, which is what makes I/O-bound nodes and SSE cheap |
| Transport | SSE | One-way server push over plain HTTP. WebSockets buy nothing when only the server talks. [Details](/configent/docs/sse-streaming) |
| Frontend | Next.js + Tailwind | Client-agnostic; branding comes from the API, not the build |

## Vocabulary

- **Client / tenant:** one assistant (sources, prompts, branding, thresholds, handoff, limits) defined by one YAML file in `config/`.
- **Template:** the graph a client runs, named for its evidence: `documents` or `database`. Config selects one; code defines it.
- **Platform:** everything that is not a template: limits, the run trail, checkpoints, the shared outcome nodes, model calls, cost, SSE.
- **Node:** one step of a graph. Each commits an entry to the step trail before the next starts.
- **Route:** the string a node writes to the state after a Python function decides it: `decide_level1`, `decide_level2` or `decide_sql`. The edges only read it.
- **Outcome:** how a turn ends: `answer` (cited), `converse` (a greeting or thanks; no ticket), `decline` (the client's fixed message) or `ticket` (a drafted ticket, filed on confirmation).
- **Handoff:** what a client does when a turn cannot be answered. `mode: message` declines; `mode: ticket` offers a ticket.
- **Triage:** the `kind` field on a template's first model call (`question`, `conversation`, `handoff`). It replaces an intent router in front.
- **Chunk:** a passage of a document (512 tokens for DeployBot), embedded in pgvector. Retrieval returns chunks, so a citation can point at a paragraph.
- **Similarity:** `1 - cosine_distance` between the question's vector and a chunk's. DeployBot discards anything below `0.3`.
- **Groundedness:** the grade call's score for whether the passages support an answer. Similarity says "close"; groundedness says "sufficient".
- **Level / tier:** documents only. Level 1 is RAG, Level 2 is corrective RAG, Level 3 is the handoff.
- **Guard:** database only. The layers that decide whether a model-written query may run.
- **Run:** one turn, and the durable step trail it leaves in Postgres.
- **Checkpoint:** LangGraph's saved state after a node, keyed by the run id. What lets a turn pause on a ticket offer and continue in a later request.
