<div class="lead">
  Configent is a multi-tenant RAG assistant platform where a client is a YAML file, not a codebase.
  The reference client is a Google Cloud support agent that answers from documentation with
  citations and files a ticket when it can't.
</div>

## What it has to do

Four requirements, and every design decision below traces back to one of them.

1. **Answer only from the corpus, with citations.** An uncited claim is a failure, not a style choice.
2. **Know when it cannot answer.** The interesting half of a support agent is the refusal, and that decision has to be explainable after the fact.
3. **Serve many clients from one deployment.** Adding a tenant is a config file, a corpus, and a prompt — no Python.
4. **Leave a record.** Every turn has to be auditable, and the record has to survive the process dying mid-turn.

## The shape

```
Next.js (chat UI)          apps/web
      │  SSE
FastAPI                    apps/api
      ├─ config registry    one YAML per client, validated at startup
      ├─ engine             loop  ─or─  pipeline   (agent.mode)
      │     ├─ retrieval    Voyage embed → pgvector cosine, scoped by client_id
      │     ├─ Anthropic    Messages API — citations, structured output
      │     └─ tools        plain dict registry
      └─ Postgres           conversations · messages · chunks+embeddings · runs · traces
                                  │  HTTP
                            mock ticket service   apps/mockticket
```

One Postgres holds the relational data *and* the vectors. One process serves every tenant. The only external calls are Anthropic, Voyage, and the ticket service.

## Two engines, one contract

`agent.mode` picks which engine serves a client. Both emit the same SSE events, so the frontend never knows which ran.

| | `loop` | `pipeline` |
|---|---|---|
| Control flow | Model picks tools until it stops | Fixed stages, one branch |
| Escalation decided by | The model | An `if` statement in Python |
| Good for | Open-ended work | A decision you have to justify |
| Walkthrough | [Agent Loop](/configent/docs/agent-loop) | [The Answer Pipeline](/configent/docs/pipeline) |

The support agent runs `pipeline` because its whole claim is that escalation is not the model's decision — and a model holding the ticket tool cannot make that claim.

**[The Answer Pipeline](/configent/docs/pipeline) is the section to read next.** Its hub page follows one question end to end; the six pages under it own one component each.

## The stack, and why

| Layer | Choice | Why this one |
|---|---|---|
| LLM | Anthropic Claude (Haiku 4.5) | Native citations and structured output are both first-class; Haiku is cheap enough to spend a second call on scoring |
| Embeddings | Voyage `voyage-3` | Anthropic has no embeddings API, so a third party is required either way. Voyage exposes `input_type` query/document — [free recall win](/configent/docs/ingestion-pipeline#why-voyage-ai) |
| Vector store | pgvector | Already inside the Postgres we need. A dedicated vector DB would be a [second service for no gain at this scale](/configent/docs/ingestion-pipeline#voyage-ai-vs-pgvector) |
| Backend | FastAPI + async SQLAlchemy | Native `async` all the way down, which is what makes concurrent tool calls and SSE cheap |
| Agent runtime | Hand-rolled | No LangChain or LangGraph. [One file](/configent/docs/agent-loop) covers tool execution, cost, caching, and streaming — a framework would hide exactly the parts worth showing |
| Transport | SSE | One-way server push over plain HTTP. WebSockets buy nothing when only the server talks — [details](/configent/docs/sse-streaming) |
| Frontend | Next.js + Tailwind | Client-agnostic; branding comes from the API, not the build |

## Vocabulary

The terms the rest of the docs use without re-defining.

- **Client / tenant:** one assistant — corpus, prompt, tools, branding, limits — defined by one YAML file in `config/`.
- **Chunk:** a passage of a document (512 tokens for the support agent), embedded and stored as a row in pgvector. Retrieval returns chunks, not documents, so a citation can point at a paragraph.
- **Similarity:** `1 - cosine_distance` between the question's vector and a chunk's. Ranges 0–1; the support agent discards anything below `0.3`.
- **Groundedness:** a separate cheap-model score for whether the retrieved passages actually support an answer. Similarity says "close"; groundedness says "sufficient".
- **Stage:** one step of the pipeline engine — `retrieve`, `score`, `answer`, `escalate`, `ticket`. Each commits an audit entry before the next starts.
- **The two signals:** retrieval similarity (is anything in the corpus close?) and groundedness (is it enough?). One catches a corpus with nothing relevant; the other catches a corpus with something close but wrong.
- **The branch:** the single `if` statement that decides answer-or-escalate. Everything else is a stage; only this decides.
- **Tool starvation:** the answering call is sent no tool definitions at all, so escalation is unreachable from inside the model. A guarantee, not a prompt instruction.
- **Run:** one pipeline turn, and the durable step trail it leaves in Postgres.
- **Tool:** a function the model can ask the backend to call. The pipeline's answering call is sent none.
