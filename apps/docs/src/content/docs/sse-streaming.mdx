The chat endpoint returns a `StreamingResponse` immediately. As the agent loop runs, it yields SSE frames (text deltas, citation events, tool status) that the frontend consumes incrementally.

SSE works over plain HTTP with no upgrade handshake and passes through any proxy. For server→client-only streaming, WebSockets add complexity for no benefit.

---

## Event contract

Every frame is `event: <name>\ndata: <json>\n\n`.

Both engines emit the same contract. `tool` frames come only from the loop; `run` and
`step` frames come only from the pipeline. Everything else is shared.

| Event | Payload | When | Engine |
|---|---|---|---|
| `run` | `{run_id, conversation_id}` | Once, before the first stage | pipeline |
| `step` | `{seq, stage, status, reasoning, latency_ms, ts, …}` | As each stage finishes | pipeline |
| `tool` | `{name, status: "start"\|"end"}` | Before and after each tool call | loop |
| `text` | `{delta: str}` | Each text chunk from the model | both |
| `citation` | `{index, source, title, cited_text}` | Each inline citation | both |
| `done` | `{conversation_id, input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens, cost_usd, latency_ms}` | After DB commit | both |
| `error` | `{message: str}` | On any exception — replaces `done` | both |

A pipeline `done` frame carries three extra fields the loop has no use for: `run_id`,
`escalated`, and `ticket_id`.

### The `step` event

The payload is the same dict written to `Run.steps`, returned by the same call that
persists it, so the stream and the durable record cannot disagree.
[Runs & Durability](/configent/docs/runs-and-durability#a-step-entry) lists the
stage-specific fields that ride along in it.

```
event: step
data: {"seq": 2, "stage": "score", "status": "ok", "reasoning": "The passage describes quota limits in general, not this project's.", "confidence": 0.05, "latency_ms": 812, "ts": "2026-08-30T14:22:07.145128+00:00", "cost_usd": 0.0011}
```

**Unknown events are dropped silently** by the frontend's `handleEvent`. That is why
backend work on a new event type stays invisible until the client learns to render it.

Example sequence for a single `search_docs` call in the loop:

```
event: tool
data: {"name": "search_docs", "status": "start"}

event: tool
data: {"name": "search_docs", "status": "end"}

event: text
data: {"delta": "The PX-900 filter "}

event: citation
data: {"index": 1, "source": "corpora/acme-fab/px900-maintenance.md", "title": "PX-900 Maintenance Guide", "cited_text": "Replace the intake filter every 500 operating hours..."}

event: text
data: {"delta": "should be replaced every 500 operating hours."}

event: done
data: {"conversation_id": "...", "cost_usd": 0.000312, "latency_ms": 1840, ...}
```

A pipeline turn that escalates instead:

```
event: run
data: {"run_id": "3f2b...", "conversation_id": "..."}

event: step
data: {"seq": 1, "stage": "retrieve", "status": "ok", "n_hits": 5, "top_similarity": 0.5031, ...}

event: step
data: {"seq": 2, "stage": "score", "status": "ok", "confidence": 0.05, "supported": false, ...}

event: step
data: {"seq": 3, "stage": "escalate", "status": "ok", "category": "quota_or_billing", "priority": "high", ...}

event: step
data: {"seq": 4, "stage": "ticket", "status": "ok", "ticket_id": "PLATFORM-1043", "queue": "platform-serverless", ...}

event: text
data: {"delta": "I can't answer that from the documentation — I've opened PLATFORM-1043."}

event: done
data: {"conversation_id": "...", "run_id": "3f2b...", "escalated": true, "ticket_id": "PLATFORM-1043", ...}
```

> **The escalation reply is a `text` event too.** A streaming client renders it exactly
> like an answer. Without it the UI shows a step trail above an empty bubble, which reads
> as a crash rather than a decision.

## FastAPI endpoint

```python
@router.post("/c/{client_id}/chat/stream")
async def chat_stream(client_id: str, req: ChatRequest):
    cfg = get_registry().get(client_id)

    async def event_source():
        async with AsyncSessionLocal() as db:
            async for name, data in stream_turn(
                req.message, cfg=cfg, client_id=client_id,
                conversation_id=req.conversation_id, db=db,
            ):
                yield f"event: {name}\ndata: {json.dumps(data)}\n\n"

    return StreamingResponse(
        event_source(),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )
```

The endpoint opens the DB session inside `event_source()`, not via `Depends(get_db)`. A `Depends`-scoped session closes before `StreamingResponse` starts writing. The session is gone by the first yield.

`X-Accel-Buffering: no` prevents nginx from holding the entire stream and releasing it as one chunk.

## `stream_turn` and `_stream_loop`

`stream_turn` is an async generator that handles setup, error recovery, and the `done` event:

```python
async def stream_turn(user_message, *, cfg, client_id, conversation_id, db):
    started = time.monotonic()
    conversation_id, history = await _prepare_conversation(db, client_id, conversation_id)
    result = LoopResult(messages=messages)
    try:
        async for event in _stream_loop(messages, ..., result=result):
            yield event
    except anthropic.APIError as exc:
        await db.rollback()
        yield ("error", {"message": f"Upstream API error: {exc.__class__.__name__}"})
        return
    except Exception as exc:
        await db.rollback()
        yield ("error", {"message": str(exc)})
        return

    await _persist_turn(db, conversation_id, len(history), result)
    await db.commit()
    yield ("done", {"cost_usd": round(result.usage.cost_usd, 6), ...})
```

Errors call `db.rollback()` before yielding `error`. HTTP headers are already sent by that point, so there is no other way to signal failure.

`_stream_loop` translates raw Anthropic SDK events into UC-10 tuples:

```python
async with aclient.messages.stream(**_request_kwargs(...)) as stream:
    async for event in stream:
        if event.type == "content_block_start":
            if event.content_block.type == "tool_use":
                yield ("tool", {"name": event.content_block.name, "status": "start"})
        elif event.type == "content_block_delta":
            if event.delta.type == "text_delta":
                yield ("text", {"delta": event.delta.text})
            elif event.delta.type == "citations_delta":
                yield ("citation", {"index": citation_index, ...})
    response = await stream.get_final_message()
```

`get_final_message()` returns the completed response after the stream closes. The `usage` struct for cost accounting comes from this response. `_stream_loop` emits `tool` `status: "end"` after `asyncio.gather` completes, so the frontend knows exactly when a tool call finishes.

## Frontend

`ChatPanel.tsx` uses `fetch` POST rather than `EventSource` (which is GET-only):

```typescript
const response = await fetch(`/api/c/${clientId}/chat/stream`, {
  method: "POST",
  body: JSON.stringify({ message, conversation_id: conversationId }),
  headers: { "Content-Type": "application/json" },
});

for await (const { event, data } of parseSse(response.body!.getReader())) {
  handleEvent(event, data);
}
```

`handleEvent` drives React state:

| Event | Effect |
|---|---|
| `tool start` | Shows a "Searching…" indicator |
| `tool end` | Removes the indicator |
| `text` | Appends `delta` to the current message |
| `citation` | Attaches a numbered popover to the preceding text segment |
| `done` | Stores `conversation_id`; renders cost + latency badge |
| `error` | Renders the error inside the assistant bubble |

Text and citations arrive interleaved, so the frontend builds `{ text, citations[] }` segments rather than a flat string. Segments with citations render as hoverable spans showing the source document and cited passage.

## Next.js proxy route

Browser requests go to the Next.js API route at `apps/web/app/api/c/[client_id]/chat/stream/route.ts`, which proxies to FastAPI:

```typescript
export async function POST(req: Request, { params }) {
  const upstream = await fetch(
    `${process.env.API_URL}/api/c/${params.client_id}/chat/stream`,
    { method: "POST", body: req.body, duplex: "half" }
  );
  return new Response(upstream.body, {
    headers: { "Content-Type": "text/event-stream" },
  });
}
```

The proxy keeps the FastAPI origin off the browser and handles CORS in one place.

## Note: Streamable HTTP

Streamable HTTP is the MCP spec's (2024-11-05) replacement for HTTP+SSE as an MCP server transport. It lets a single endpoint respond with either plain JSON or an SSE stream, and adds session management (`initialize` handshake, `Mcp-Session-Id` header, capability negotiation).

That overhead suits MCP servers serving external clients like Claude Desktop, not a custom chat API with a fixed event contract that always streams. If Configent ever exposes its tools as an MCP server, Streamable HTTP would be the right transport for that surface.
