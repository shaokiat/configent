## The graph

```
generate ─┬─ converse / handoff         (the same call classifies the message)
          └─ guard → execute ─┬─ answer
                              └─ repair → guard → execute ─┬─ answer
                                                           └─ handoff

handoff = decline (mode: message) or escalate → ticket (mode: ticket)
```

As LangGraph compiles it, drawn from the code:

<Mermaid diagram={database} maxHeight={480} />

- **`generate`** classifies the message as `question`, `conversation` or `handoff` and writes the SQL in one structured call.
- **`guard` and `execute` are separate nodes,** so the step trail tells a rejected query from a failed one.
- **`answer` is a separate call from `generate`.** `generate` returns JSON; `answer` streams prose that cites `[n]`. The split falls along node lines, as in the documents graph.
- **The rows are passage `[1]`,** sourced as `sql://<client_id>`, and the answer cites them as `[1]` (D15). The answering call has no `tools` key (D2).
- **`converse`, `decline`, `escalate` and `ticket` are the shared nodes.** See [One Turn, End to End](/configent/docs/one-turn#how-a-turn-ends).

## The guard, in layers

A model-written query is untrusted input. Each layer catches something the one before cannot.

| Layer | Where | What it stops |
|---|---|---|
| **Read-only open** | `open_readonly`: `mode=ro` plus `PRAGMA query_only=ON` | Any write to the file |
| **Authorizer** | `set_authorizer`, allow-list of SELECT, READ, FUNCTION, RECURSIVE | `ATTACH` of another file, `PRAGMA`, every write action, including ones a future SQLite adds |
| **Parser** | `sqlglot` in `guard.check` | Multiple statements, non-SELECT statements, writes inside a CTE, each with a readable reason |
| **`EXPLAIN`** | on the read-only connection | Unknown tables and columns, before the query runs |
| **Timeout** | progress handler, `guard.timeout_ms` (5000) | A runaway query |
| **Row cap** | `guard.row_limit` (200), one extra row fetched to detect truncation | A huge result set; the answer is told it is partial |
| **Cell cap** | 500 characters per value; blobs shown as `<N bytes>` | One giant cell dominating the prompt |

- **The connection mode and authorizer are the real guard.** If the parser and the connection ever disagree, the connection wins.
- **The parser exists for explanations.** A rejection the model can read ("write inside a CTE: DELETE") is what makes the repair step work.
- **Deny by default.** `mode=ro` alone does not stop `ATTACH`, which could expose another file on disk.

## Repair, and `decide_sql`

```python
def decide_sql(*, verdict, error, attempts, cfg) -> tuple[str, str]:
    # no failure           -> "answer"
    # attempts < repair_attempts -> "repair"
    # otherwise            -> "escalate"
```

- **Python routes, the model does not.** The nodes store the route; the edges only read it (D2).
- **A failed query is repaired, not regraded.** `repair` gets the query and the error and writes a corrected one, and it goes back through the guard.
- **`agent.repair_attempts`** (default 2, at most 3; `f1-analyst` sets 1) bounds the loop. When it is spent, the turn escalates with the last error as `why`.
- **Zero rows is an answer.** The query ran, and "nothing matches" is true evidence. The answer says "no matching records" and does not guess why, so it never blames the data or invents a cause.
- **No groundedness grade.** The SQL either ran or it did not, so this template has no `confidence` in its `done` payload, only `row_count`.

## The ingestion contract

The template's sources are a database file and a notes folder, `corpora/f1-analyst/`.

| Input | Source |
|---|---|
| **DDL** | Introspected from the database: tables, columns, types, primary and foreign keys |
| **Column descriptions** | `descriptions/<table>.csv`, BIRD's own, shown as a comment per column |
| **Glossary and rules** | `glossary.md` and `rules.md`, written for this project |

- **`ingest` stores one `documents` row,** `schema://<client_id>`, with the rendered text and no chunks. The prompt reads it back for every call.
- **The fingerprint is a hash of the normalised DDL and every notes file.** Unchanged means skipped; `--force` rebuilds.
- **`ready` is truthful.** It reports a missing database file (`run make data-bird`), no stored context, an unreadable database, or a fingerprint that no longer matches. Chat answers 409 until it is `None`.
- **`make ingest CLIENT=f1-analyst CHECK=1`** lists undescribed columns and the context's token count (best effort) without writing.
- **Undescribed columns are visible.** A description that only repeats the column name counts as missing.

Setup: `make data-bird && make ingest CLIENT=f1-analyst`. The download is checked against a pinned SHA-256; a mismatch fails. See the [README](https://github.com/shaokiat/configent#data-and-attribution) for the BIRD licence and what is and is not redistributed.

## Config

`config/f1-analyst.yaml` selects the template and tunes it. The `handoff:` block works the same for every template.

```yaml
agent:
  template: database
  model: deepseek/deepseek-v4.1-flash
  system_prompt_file: prompts/f1-analyst/answer.md   # generate.md, ticket_draft.md beside it
  database: { dialect: sqlite, path: data/bird/formula_1.sqlite }
  context: { source: corpora/f1-analyst/ }
  guard: { row_limit: 200, timeout_ms: 5000 }
  repair_attempts: 1
handoff:
  mode: ticket
  queue: data-team
  team: data team
  categories: [missing_data, data_request, other]
```

- **`corpus:` and `retrieval:` are rejected** for this template. `extra="forbid"` names the key.
- **`handoff.team`** is who the offer and the failure text say will take the ticket. It is tenant data, not code.
- **Three prompts, not four:** `generate.md`, `answer.md` and `ticket_draft.md`. There is nothing to grade or rewrite.

## Caching and evals

- **`generate` and `repair` share one system text** (prompt plus schema context) with a cache breakpoint after it, so a repair can reuse the prefix its own `generate` wrote. Whether a provider caches it is up to the provider: [Model Calls → Caching](/configent/docs/model-calls#caching-one-breakpoint-and-the-provider-decides).
- **Triage is measured:** 20 of 22 on DeepSeek V4.1 Flash. **BIRD execution accuracy is not run yet.** Both are on [PitWall → Evals and cost](/configent/docs/pitwall#evals-and-cost).

## What is deliberately not here

- **No router and no web search.** One template, one evidence source.
- **The full schema goes in the prompt.** Schema retrieval comes when a schema no longer fits or stops caching.
- **No plug-in retrievers.** See Known gaps in the decision log, with the trigger for each.
