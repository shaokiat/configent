The guardrail is the only branch in the pipeline, and it is plain Python. It reads the two signals produced by [retrieval](/configent/docs/retrieval) and [scoring](/configent/docs/scoring), compares them to configured thresholds, and returns the decision **and the reason for it**. No model is consulted, and none can override it.

This is the component the whole engine exists to make possible.

---

## Contract

```python
def should_escalate(
    *, retrieval_confidence: float, score: dict | None, cfg: ClientConfig
) -> tuple[bool, str]
```

Escalate or not, plus a human-readable reason string. The reason is recorded on the step and reaches the UI, so every escalation carries its own justification.

## The flow

<Mermaid diagram={`
flowchart TD
    A[should_escalate] --> B{score is None?}
    B -->|yes — retrieval was empty| E[Escalate]
    B -->|no| C{top similarity &lt; escalate_below?}
    C -->|yes — signal 1| E
    C -->|no| D{groundedness &lt; confidence_threshold?}
    D -->|yes — signal 2| E
    D -->|no| F[Answer]
`} />

```python
if score is None:                                        # retrieval was empty
    return True, "retrieval returned no passages above the drop floor"
if retrieval_confidence < cfg.agent.escalate_below:      # signal 1
    return True, f"top similarity {retrieval_confidence:.2f} < escalate_below ..."
if float(score["confidence"]) < cfg.agent.confidence_threshold:   # signal 2
    return True, f"groundedness {...:.2f} < confidence_threshold ..."
return False, "... both above threshold"
```

Three checks, evaluated in order, each with its own sentence.

## Design

### Why two signals

| Signal | Source | Catches |
|---|---|---|
| **Retrieval similarity** | `hits[0].similarity` from pgvector | Nothing in the corpus is close to the question |
| **Groundedness** | The cheap scorer | The right document came back, and it does not contain the answer |

The second is the one that earns its keep:

> **The case that justifies it.** For "can you raise my Cloud Run instance quota for europe-west1?", retrieval scored **0.50** — above the 0.45 floor, so signal 1 passed. Groundedness came back **0.05**, and that forced the branch. The corpus has plenty of documentation *about* Cloud Run quota. It has nothing about *this user's* quota. Similarity alone cannot tell those apart.

One signal would fail one way or the other. Similarity alone answers confidently from a near-miss document. Groundedness alone puts the entire guardrail behind a model call.

### The rest

- **The reason string is a product feature, not a log line.** It is the answer to "why did it escalate?", it is generated by the comparison that made the decision, and it renders in the step trail the user sees.
- **The escalate path never asks a model whether to escalate.** The `escalate` stage drafts ticket fields *after* this function has already decided. See [Escalation & Ticket](/configent/docs/escalation-ticket).
- **Empty retrieval short-circuits.** `score is None` is checked first, because the scoring call was skipped and there is no number to compare.

## Configuration

<a id="three-thresholds"></a>

| Key | Default | Job |
|---|---|---|
| `retrieval_drop_floor` | `0.3` | **Discards** weak chunks before the model sees them |
| `escalate_below` | `0.45` | **Escalates** when the best surviving chunk is still weak |
| `confidence_threshold` | `0.6` | **Escalates** when the scorer says the passages do not support an answer |

The first two operate on the same number at different points, so their ordering matters. Every surviving hit is at or above the drop floor by construction, so if `escalate_below <= retrieval_drop_floor`, signal 1 can never fire — the guardrail would look configured and be half dead. The config validator rejects that relationship at startup:

```python
if self.mode == "pipeline" and self.escalate_below <= self.retrieval_drop_floor:
    raise ValueError(...)
```

Keys in full: [Config Reference](/configent/docs/config-reference#agent).

---

## Edge cases

- **A malformed score.** `score.get("confidence", 0.0)` means a judgement missing its number escalates. Failing toward the human is the correct default for a support agent.
- **Both thresholds set to `0`.** Legal, and it disables escalation for everything except empty retrieval. That is a deliberate config choice, so the validator allows it.

---

## On the record

The reason string rides on whichever stage came next:

```json
{ "stage": "score",    "confidence": 0.05, "supported": false }
{ "stage": "escalate", "reasoning": "groundedness 0.05 < confidence_threshold 0.6",
  "category": "quota_or_billing", "priority": "high" }
```

There is no `branch` step. The decision is recorded as the reason on the stage it produced, which keeps the trail one entry per unit of work.
